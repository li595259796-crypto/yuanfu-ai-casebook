# 元附企业 AI 智能化升级案例册设计规格

## 目标

为中国联通 AI 负责人及其企业客户制作一份可在线演示的企业 AI 案例册。页面要证明元附具备从企业诊断、流程拆解、知识编译、AI 工作流重构到智能体落地的完整交付能力，而不是展示一组孤立工具。

## 核心定位

主标题为“元附的数字宇宙”。核心定义为“企业 AI 智能化升级服务商”，核心能力为“AI 工作流改造 × 企业智能体建设”。主张为“让系统负责执行，让人负责判断与创造”。

## 受众与成功标准

- 受众：联通 AI 负责人、联通政企团队、大型企业管理者。
- 首屏在 10 秒内说明元附是谁、解决什么问题。
- 读者能看懂元附的方法论、真实业务结果和可复制的行业能力。
- 页面在桌面和移动端均完整可用；核心内容不依赖悬停。
- GitHub Pages 可直接部署，所有关键素材本地化，不依赖 MotionSites、Figma 或 CloudFront 外链。

## 信息架构

1. Hero：元附定位、价值主张、数字宇宙视觉。
2. 企业挑战：数据、知识、流程、经验四类问题。
3. 方法论：企业诊断 → 流程拆解 → AI 机会识别 → Workflow 重构 → 应用落地 → 智能体建设 → 持续优化。
4. 能力矩阵：设计、生产、运营、知识、行业智能体五类能力。
5. 案例册：5 张 sticky stacking 案例卡片。
6. 企业 AI OS：数据层、知识层、Workflow 层、Agent 层、数字员工体系。
7. 联通合作：联通连接企业需求，元附负责 AI 落地。
8. 结尾：行动主张与联系方式占位。

## 案例与事实边界

### WB POD 跨境电商工作流

- 客户描述：某俄罗斯跨境电商 POD 服装卖家。
- 原流程：选品、设计、P 图、文案、SKU 整理、平台上架。
- 已确认结果：6–8 人团队缩减为 1–2 人管理审核；单套产品由 1 天缩短至 30 分钟；原团队日均约 200 条商品链接。
- 表达边界：这是按客户业务设计并落地 AI 工作流的案例，不称作通用 ERP。

### 专业服务机构智能体

- 对外统一称“某知识密集型专业服务机构”。
- 流程：全量资料整理、知识编译、关系网络、按业务需求构建智能体。
- 已确认结果：部分原需两三天的工作缩短至两三个小时。
- 不出现机构、律师、人员姓名、案件或其他可追溯信息。

### dyLIVE

- 表达为“AI 直播运营分析能力”，不承诺销售增长结果。
- 展示 CTA 密度、互动提问密度、卖点密度、福利/价格表达、库存/倒计时、直播有效时段和竞品对比等量化分析过程。

### AI 客服知识运营平台

- 表达为“企业知识运营与智能体平台”。
- 能力包括知识中台、RAG、AI 服务、客服工作台、H5/小程序 AI 助手、日志审计和 SaaS 管理。
- 当前界面数字仅作产品界面演示，不当作客户成效数据。

### Dreamsmaker

- 表达为“AI 设计生产力平台”。
- 场景包括淘宝电商图片、游戏人物设计和短剧视觉创作。
- 当前截图先作为产品能力图，后续可无代码替换真实用户案例素材。

## 视觉与交互

- 主色为 #0C0C0C，使用银灰渐变标题、暖橙与青绿色作数据强调。
- 视觉参考来自 MotionSites 的高级动效节奏和 3D Portfolio 模板，但不复制人物、装饰物、外链 GIF 或作品图。
- Hero 使用原创的企业数据宇宙图片，叠加轻量 CSS 节点、网格和漂浮效果。
- 方法论使用纵向/横向步骤流；能力矩阵使用大号编号列表；案例区使用 sticky stacking cards。
- 支持 reduced-motion，避免影响阅读的连续大幅动画。
- 案例截图使用大圆角、局部放大和清晰图注；包含隐私的原始聊天截图不直接公开。

## 技术架构

- React 18、TypeScript、Vite、Tailwind CSS 3、Framer Motion、Lucide React。
- 单路由静态站点，适配 GitHub Pages 子路径。
- 文案和图片清单集中在 `src/data/siteContent.ts`，图片位于 `public/assets/`。
- Vitest 与 Testing Library 验证关键内容、导航和数据结构；Vite build 验证生产产物。
- GitHub Actions 构建并部署 `dist` 到 GitHub Pages。

## 安全与隐私

- 图片素材进入项目前复制并改为语义化文件名。
- 不发布带真实姓名的需求沟通截图和微信反馈截图；客户反馈改写为匿名引用卡片。
- 不暴露本机用户名、内部域名、邮箱、账号或可追溯客户信息。
